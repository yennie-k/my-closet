# 의류 편집 미저장 변경사항 보호 — 2026-11-09

## 적용한 동작

일반 IndexedDB 옷장과 서버 개발 옷장의 공통 `GarmentEditorScreen`에서 변경사항이 있으면 뒤로가기 전에 다음 확인창을 표시한다.

- 제목: **변경사항이 저장되지 않았어요**
- 본문: **저장하지 않고 나가면 이번에 변경한 내용이 사라집니다. 정말 나가시겠어요?**
- **계속 수정**: 확인창만 닫고 입력과 사진 선택을 유지한다.
- **저장하지 않고 나가기**: 저장이나 사진 업로드를 시작하지 않고 편집 화면을 닫는다.

변경사항이 없으면 바로 닫힌다. 확인창을 Esc/뒤로가기/바깥 영역으로 닫아도 편집을 유지한다. 같은 이탈 요청이 반복되어도 확인창을 중복으로 띄우지 않는다.

## 변경사항 판단 방식

편집 화면이 처음 생성될 때 초기 상태의 메모리 내 스냅샷을 만들고 현재 상태와 비교한다. 신규 화면은 빈 초기 상태, 기존 수정 화면은 실제로 불러온 값이 기준이다. 스냅샷은 DB·브라우저 저장소·로그에 저장하지 않는다.

비교 대상은 이름, 카테고리, 적용된 세부 종류, 미적용 세부 종류 텍스트, 대표/추가 색상, 미추가 색상 텍스트, 계절, 두께, 스타일 태그, 소재 목록, 미추가 소재 텍스트, 핏, 메모, 기존 사진 유지 여부, 새 사진 선택 상태다. ID·등록일·수정일·진행 안내·검증 오류·펼친 섹션·포커스·커서 위치는 변경 판단에서 제외한다.

다중 선택은 선택한 항목의 순서를 의미로 사용하지 않으므로 정렬한 복사본을 비교한다. 항목을 뺐다가 다시 추가해 순서만 바뀐 경우 경고하지 않는다. 텍스트는 최종 입력값을 비교하며 원래대로 되돌리면 변경 상태가 해제된다. 확인되지 않은 직접 입력도 잃어버리지 않도록 소재·추가 색상 위젯에서 입력 중 텍스트를 부모에 알린다. 경고를 위해 ‘추가’나 ‘종류 적용’을 강제로 실행하지 않는다.

새로 선택한 사진의 바이트 해시를 메모리에서 한 번 계산해 선택 상태에 포함한다. 원본 사진은 비교를 위해 다시 다운로드하거나 읽지 않는다. 따라서 기존 사진이 있는 상태에서 파일을 새로 선택하면 변경으로 취급한다. 서버의 선택 취소 또는 신규 사진 선택 후 제거로 초기 사진 상태에 돌아오면 깨끗한 상태가 된다. 동일한 원본 파일을 다시 고른 것을 자동으로 ‘원본과 같은 사진’이라고 판정하는 기능은 아니다.

카테고리·핏 초기화 규칙은 바꾸지 않았다. 분류 변경을 취소해서 실제 입력이 같으면 경고가 없고, 확인 후 임시 값이 바뀌었으면 경고한다.

## 화면 이탈 경로

| 경로 | 처리 |
| --- | --- |
| 편집 화면 AppBar 뒤로가기 | 동일한 미저장 확인 함수 호출 |
| Android/Flutter 시스템 뒤로가기 이벤트 | `PopScope<Garment>`에서 변경·작업 상태를 보고 차단/확인 |
| 현재 앱의 `Navigator.maybePop` | 같은 PopScope 확인 경로 |
| 서버 개발 옷장 상단 뒤로가기 | 중첩 Navigator의 현재 편집/상세 화면부터 뒤로가기 |
| 서버의 ‘이 기기 옷장으로 돌아가기’ | 활성 편집 화면에 이탈 허용을 요청한 뒤 워크스페이스 종료 |
| 사용자가 누른 서버 로그아웃 | 활성 편집 화면의 확인을 거쳐 로그아웃 |
| 브라우저가 Flutter에 전달하는 앱 내 뒤로가기 | Flutter PopScope 경로 |
| 문서를 벗어나는 브라우저 뒤로가기·새로고침·탭 닫기 | 변경/작업 중에 등록한 `beforeunload`의 브라우저 기본 경고 |

서버 워크스페이스와 편집 화면 사이에는 단일 활성 편집 요청만 가진 `EditorExitCoordinator`를 둔다. 모델이나 사진 데이터는 보관하지 않으며, 편집 화면이 제거되면 요청을 해제한다. 강제 로그아웃·토큰 상실·계정 변경으로 워크스페이스를 폐기하는 기존 보안 처리는 막지 않는다. 사용자 확인을 기다리며 이전 계정의 사진을 화면에 유지하지 않는다.

임의의 외부 코드가 `removeRoute`/`pushReplacement`/직접 강제 pop 또는 위젯 트리 교체로 화면을 없애는 모든 경로를 포괄하는 기능은 아니다. 현재 제공하는 편집 뒤로가기·서버 바깥 이동·사용자 로그아웃 버튼을 가드 경로에 연결했다.

## 저장과 사진 실패

저장·사진 선택/처리·분류 확인 중에는 잘못된 뒤로가기를 막는다. 중복 저장은 기존 작업 플래그와 입력 차단을 유지한다. 저장 성공 시에는 전체 작업 완료 이후에만 이탈을 허용하고 브라우저 경고를 해제한다. 메타데이터 저장만 성공하고 사진 검증이 실패하면 폼을 그대로 유지하고 다시 나가려 할 때 경고한다.

사진 선택만으로 저장·업로드를 시작하지 않는다. ‘나가기’ 확인은 저장소 호출 없이 화면을 닫는다. 기존 작업에서 이미 서버 메타데이터가 저장된 **부분 성공**은 이탈 확인으로 롤백하지 않는다. 이는 이전부터 존재한 사진 작업 계약이며, 이번 기능은 아직 저장하지 못한 편집·선택 사진을 버릴지 확인하는 것이다. 이미 저장된 서버 정보를 자동 삭제하는 작업은 하지 않는다.

## 브라우저 지원 범위

웹 전용 구현은 `dart:js_interop`으로 `beforeunload` 리스너를 등록/해제한다. 네이티브/VM에서는 조건부 export로 브라우저 API를 포함하지 않는다. 패키지를 추가하지 않았다. 리스너는 변경사항이나 진행 중 작업이 있을 때만 등록하며 원래 값 복원·저장 성공·이탈·dispose 시 해제한다. unload 중에는 저장, 업로드, 비동기 API를 실행하지 않는다.

브라우저 기본 경고의 문구·버튼은 앱에서 바꿀 수 없다. 사용자 조작이 선행되어야 표시될 수 있고, 모바일 백그라운드 종료·브라우저/OS 강제 종료·크래시 등에서는 보장되지 않는다. 자동 초안 저장 기능을 구현한 것은 아니다. [MDN beforeunload 안내](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event), [Flutter PopScope 문서](https://api.flutter.dev/flutter/widgets/PopScope-class.html)에 따른 제한이다.

## 검증

신규 테스트는 미변경/포커스만 이동, 이름·핏·색상·메모 복원, 다중 선택 순서 복원, 미적용 종류/소재/색상, 분류 변경 확인/취소, 사진 선택/제거/교체 취소, 저장 성공/실패/대기, 사진 검증 대기 후 실패, 시스템 뒤로가기, 서버 외부 종료·로그아웃, 3개 테마의 모바일 확대 글씨 확인창을 검사한다. 실제 DB가 아닌 별도 합성 모델·사진과 메모리 저장소를 사용한다.

격리된 **Edge InPrivate, 8082, 합성 전용 앱**에서는 실제 Chromium 기본 경고 이벤트를 관찰했다. 새로고침·이전 문서로 뒤로가기·탭 닫기를 시도한 뒤 기본 경고에서 취소하면 합성 입력이 유지되었다. 초기 화면·복원된 텍스트·편집 폐기 뒤에는 리스너가 없고 깨끗한 새로고침이 가능했다. 최종 **10 통과 / 0 실패**다. 사용자 8080/8081 브라우저 프로필은 열지 않았다.

초기 자동화에서 비어 있는 입력의 일시적인 접근성 라벨을 다시 찾지 못한 테스트 보조 오류가 있어, 이미 포커스된 입력에 실제 키 입력을 보내도록 보완했다. 서버 외부 종료 테스트는 테스트의 실제 MediaQuery 크기를 데스크톱으로 설정하도록 수정했다. 이전 ‘바로 뒤로가기’ 기대값은 새 확인창 선택으로 갱신했다. 보호 기능을 우회하도록 운영 코드를 변경하지 않았다.

전체 회귀에서는 새로 추가한 중첩 Navigator의 GlobalKey를 계정 전환에 재사용해 이전 화면이 남는 오류가 발견됐다. 계정 ID·세션 generation 경계마다 새 Navigator 키를 사용하도록 고쳤다. 기존 계정 전환 회귀와 함께, 변경 중인 A 편집 화면을 강제 B 전환으로 제거하고 B의 이탈 확인이 A의 콜백을 재사용하지 않는 테스트를 추가했다. 강제 인증 변경은 기존처럼 사용자 확인을 기다리지 않고 이전 비공개 화면을 제거한다.

## 데이터 보호와 수동 확인

모델 v2·서버 DTO·저장소·옵션·사진 처리·SQL·worker 등 기존 보호 대상 34개 소스의 전후 해시가 동일했다. 카테고리 초기화 규칙과 JPEG restart 호환 처리는 수정하지 않았다. 실제 IndexedDB 옷 3벌, 서버 아이보리 셔츠·고양이·브라운 코트 및 사진에 읽기/쓰기 요청을 보내지 않았다. 마이그레이션·DB 초기화·클라우드 연결/배포·Git commit/push도 하지 않았다.

실제 앱 확인 전 Flutter를 완전히 재시작한다. 브라우저 저장소는 지우지 않는다.

```powershell
flutter run -d edge --web-hostname=localhost --web-port=8081 --dart-define-from-file=config/supabase.crud.local.json
```

안전한 수동 확인은 새 등록 폼에서 이름만 입력하고 뒤로가기→계속 수정→뒤로가기→저장하지 않고 나가기로 진행한다. 사진을 골라도 저장 버튼을 누르지 않으면 업로드하지 않는다. 기존 실제 의류를 확인할 때도 저장하지 않고 나가면 원본을 변경하지 않는다. 저장까지의 검증은 별도 합성 의류로 수행한다.
