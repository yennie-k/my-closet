# 카테고리·세부 종류별 입력 UX 개선 — 2026-11-09

추가 보완: 이 문서의 기존 ‘분류 변경 후 값 유지’ 동작은 [카테고리·세부 종류 전환 시 임시 입력 정리](category-transition-20261109.md)에서 개선했다. 현재는 신규 등록에서는 부적합한 임시 값을 정리하고 기존 수정에서는 사용자 확인 후 정리한다. 아래 검증 결과는 최초 개선 당시의 기록이다.

## 확인한 문제

실제 저장 카테고리는 `tops`, `bottoms`, `outerwear`, `dresses`, `shoes`, `bags`, `accessories`, `other`의 8개다. 표시 이름과 `subtypeSuggestions`의 57개 기본 세부 종류는 변경하지 않았다. 일반 IndexedDB 옷장과 서버 개발 옷장은 모두 `GarmentEditorScreen`과 같은 입력 위젯을 사용한다.

기존 `fitContextFor`는 `outerwear`를 `tops`로 분류했다. `FitSelector`는 이를 근거로 ‘상의 기준 실루엣’을 표시했고, `FitSilhouettePainter`는 상의 기본 분기로 티셔츠를 그렸다. 다음 문제도 확인했다.

- 코트·패딩·재킷의 설명과 윤곽이 구분되지 않았다.
- 세트·점프수트에는 같은 옷걸이 아이콘을 사용했다.
- 반바지에도 발목까지의 긴 바지 설명과 그림이 사용될 수 있었다.
- 민소매에도 소매에 관한 핏 설명이 사용됐다.
- 카테고리를 바꿔도 이전 핏을 그대로 저장할 수 있었으며 현재 추천과 맞는지 안내하지 않았다.
- 신발·가방·하의 등의 두께 예시에 티셔츠 등 다른 카테고리 예시가 사용됐다.

핏은 기존 문자열을 그대로 사용한다. 소매 길이·총장·밑창 높이 등의 새 속성을 핏 선택지에 섞지 않았다. 그림의 소매·기장은 의류 종류를 알아보기 위한 예시이며 실제 치수의 추정값이 아니다. 모든 그림은 기존 `CustomPainter` 구조를 재사용한 코드이고 외부 이미지는 추가하지 않았다.

코드로만 렌더링한 [실루엣 확인 이미지](../../build/fit-ux-20261109/illustrations.png)는 로컬 `build` 산출물이다. 실제 사용자 사진은 포함하지 않는다.

## 다른 입력 항목 검토

- 세부 종류 추천과 직접 입력을 유지한다. 다른 대분류의 알려진 추천 종류가 남아 있으면 값을 지우지 않고 확인 안내를 표시한다. 미등록 사용자 지정 종류도 계속 입력·저장할 수 있다.
- 대표·추가 색상, 18색 팔레트·HEX 연결, 중복 방지, 직접 입력은 변경하지 않았다.
- 소재 복수 선택·혼방 입력·기존 원문 보존과 `FabricPatternPainter` 질감 그림은 변경하지 않았다. 실제 원단 사진이 아닌 직접 그린 참고 일러스트라는 기존 안내도 유지한다.
- 두께의 1~5 수치·저장 이름은 동일하다. 카테고리에 맞는 예시를 사용하고 신발·가방 등에서는 비교하기 어려우면 비워도 된다고 안내한다. 굽/밑창 높이·가방 크기·보온성의 대체값으로 사용하지 않는다.
- 계절은 주로 사용하는 계절의 복수 선택, 스타일 태그는 아이템 분위기라는 안내를 추가했다. 모두 선택 사항이며 기존 값과 선택 동작을 유지한다.

## 기존 값과 저장 동작

1. 카테고리·세부 종류 변경은 핏 선택지·설명·그림만 즉시 갱신한다. 입력된 핏·세부 종류를 자동으로 삭제하거나 대체하지 않는다.
2. 현재 추천에 없는 핏은 섹션 요약과 입력란에 확인 안내를 표시한다. 이는 기존 값과 사용자 지정 값 모두에 적용한다.
3. 실제 변경 내용을 저장하려면 ‘입력한 핏을 유지할까요?’에서 **이 핏으로 저장**을 선택해야 한다. 돌아가거나 닫으면 저장·업로드를 진행하지 않고 폼과 기존 데이터를 유지한다. 추천을 선택하거나 핏을 비우면 확인 창이 필요 없다.
4. 아무것도 바꾸지 않은 기존 의류는 기존 무변경 저장 경로를 유지한다. DB 쓰기·확인 창 없이 닫으므로 ID·수정일·사진을 건드리지 않는다.
5. 확인 절차는 저장소 호출 전에 실행한다. 서버에는 기존 `saveWithOriginal(garment, original: old)`를 그대로 전달하므로 revision 조건부 갱신·충돌 처리를 유지한다.

모델 v2·서버 DTO·직렬화·역직렬화·DB 스키마는 변경하지 않았다. 마이그레이션이나 일괄 변환은 없다. 수정일은 기존과 같이 실제 정보 변경을 저장할 때만 갱신한다.

## Edge 수동 확인

앱을 완전히 종료한 뒤 개발 모드를 다시 실행한다. 기존 브라우저 데이터는 지우지 않는다.

```powershell
flutter run -d edge --web-hostname=localhost --web-port=8081 --dart-define-from-file=config/supabase.crud.local.json
```

새 의류 폼에서 아우터 → 코트를 고른 뒤 핏 섹션을 열면 ‘코트 기준 실루엣’과 외투 그림이 보여야 한다. 경량 패딩·재킷·바람막이로 바꾸어 설명과 그림이 달라지는지 확인한다. 저장할 필요는 없다. 하의에서 스키니핏을 선택한 뒤 아우터·코트로 변경하면 값은 유지되고 확인 안내가 나타나야 한다. 저장 버튼의 확인 창에서 **돌아가서 확인**을 누르면 서버에는 쓰지 않는다.

기존 브라운 코트 등 실제 의류는 상세→수정에서 표시만 확인하고 취소할 수 있다. 사진 선택·변경·삭제나 저장을 하지 않아도 이번 UI 개선을 확인할 수 있다.
