# My Closet — Portfolio MVP 1.0

확정일: 2026-11-12. SK AIGEN 포트폴리오에 설명할 현재 기능 범위이며, AI 기능 완료를 뜻하는 버전명이 아니다.

## 프로젝트 소개

My Closet은 사용자가 가진 옷을 사진과 정보로 등록하고 검색·분류·관리하는 Flutter 디지털 옷장입니다. 개인 취향과 테마를 설정하고 PC와 모바일 크기에 맞는 화면을 사용할 수 있습니다. 향후 AI 코디 추천을 연결할 수 있도록 의류 모델과 저장 계층을 분리했으며, 현재 완성 범위는 옷장 관리와 로컬 Supabase 인증·사진 검증입니다.

## 사용 기술

Flutter 3.47.8 / Dart 3.13.7 / Material 3, IndexedDB(idb_shim), shared_preferences, file_selector, image 4.12.0, supabase_flutter 2.18.3, Supabase Auth·Postgres·RLS·비공개 Storage, TypeScript/Deno Edge Functions, SHA-256, Magick WASM, Flutter/Node 테스트, Git.

주 검증 환경은 Windows와 Edge/Chrome 기반 웹이다. Android/iOS용 공통 코드와 저장소 분리는 있지만 모바일 앱 출시나 실기기 검증 완료로 소개하지 않는다.

## 구현 완료

- 온보딩·취향·체감온도 설정, 전역 테마 3종, 설정 로컬 유지
- 사진과 의류 정보 등록·상세·수정·삭제, 2단계 필터와 검색, 빈 상태·실패·재시도
- 의류 모델 v2, 추가 색상·소재 복수 선택·두께 1~5·직접 입력·기존 문자열 호환
- 카테고리/세부 종류별 추천·핏 설명·자체 CustomPainter 실루엣·소재 참고 패턴
- 카테고리 변경 시 확인·임시 입력값 정리, 저장 전 원본 불변
- 미저장 변경사항 감지와 이탈 확인, 저장 실패 시 편집 상태 유지
- 브라우저 IndexedDB 메타데이터/사진의 트랜잭션 저장과 읽기
- 별도 로컬 개발 Supabase 인증·세션·서버 의류 CRUD·revision 충돌 처리
- 사진 업로드 예약과 비공개 객체 저장, 실제 크기/형식/해시/픽셀 검증 후 ready, 인증 다운로드·안전한 교체
- JPEG restart 마커가 있는 특정 입력의 디코딩 호환 경로

서버 개발 옷장과 기본 IndexedDB 옷장은 의도적으로 분리되어 있다. 로그인한다고 기존 옷이나 사진이 서버로 이전되지 않는다. 사진/의류 삭제는 기존 예약·활성 사진·보호 기간 정책의 제약을 받는다.

## 대표 기술 문제와 해결

### 1. 정상 원본 JPEG가 변환 후 줄무늬로 보이는 문제

원본 표시, Dart 디코딩 직후 픽셀, PNG 왕복, 리사이즈, JPEG 출력 단계를 비교해 restart 경계의 디코더 호환성 문제를 좁혔다. 특정 DRI JPEG만 Flutter 기본 코덱으로 읽어 RGBA를 기존 정규화 과정에 전달했고, 일반 JPG/PNG/WebP 경로는 유지했다. 자체 제작 합성 JPEG와 메모리 내 패딩으로 재현해 실제 사진을 테스트 자산으로 배포하지 않았다.

### 2. 사진 업로드 성공과 서버 검증 완료의 구분

클라이언트 업로드 확인을 ready 승인과 분리했다. 소유자·예약 경로·만료·실제 객체·크기·SHA-256·파일 내용과 픽셀을 서버에서 확인하고, revision CAS로만 ready를 갱신한다. 교체 실패 시 기존 활성 사진을 보존하고, 계정 전환 시 캐시와 이전 요청 결과를 차단한다. Storage와 DB는 별도 시스템이므로 완전한 단일 트랜잭션이라고 주장하지 않는다.

### 3. 편집 편의성과 기존 데이터 보존의 양립

카테고리 변경은 저장된 원본과 현재 폼 상태를 분리해 처리했다. 부적합한 종류·핏은 기존 의류에서 사용자 확인 후 편집 상태만 정리하고, 공통 색상·소재·메모 등은 유지한다. 미저장 경고는 최종 입력 스냅샷과 사진 선택 상태를 비교해 원래 값으로 되돌리면 경고를 해제하며, 아직 적용하지 않은 직접 입력도 감지한다.

## 기여와 AI 도구 활용의 구분

대화와 검증 기록으로 확인할 수 있는 범위는 다음과 같다.

| 주체 | 확인 가능한 활동 |
|---|---|
| 개발자 | 서비스 목표·기능 우선순위·UX 요구·데이터 보호 조건 결정, 로컬 환경 준비/복구, Edge에서 등록·수정·사진 업로드·새로고침·재로그인과 UX 문제 직접 확인, 재현 정보 제공 |
| Codex 등 AI 도구 | 요구를 바탕으로 Flutter/SQL/Edge 코드 및 테스트 작성 지원, 원인 조사·수정안·설계 초안·문서 작성, 도구를 통한 자동 검증 실행 |
| 협업 과정 | 생성한 구현을 실제 화면에서 확인하고 문제를 다시 제시해 수정·회귀 검증. 설계·구현은 이 과정을 거쳤으며 모든 코드를 개발자가 직접 작성했다고 소개하지 않음 |

AI 도구 활용 자체를 앱의 AI 추천 기능 구현과 혼동하지 않는다. 자동 테스트와 개발자 수동 확인은 서로 다른 근거로 기록한다.

## 미구현·향후 계획

AI 코디 추천, AI 의류 이미지 분석, 날씨 API, 코디 기록, 로컬→서버 수동 이전/통합, WebP 자동 최적화, 자동 고아 사진 정리·사용자별 quota, 클라우드 배포, 모바일 실기기 검증은 남아 있다. WebP는 합성 벤치마크와 설계 검토만 했으며 현재 앱은 기존 JPEG 출력을 유지한다.

다음 단계에서는 합성 데이터로 서버 환경·보안·실기기 검증을 보완하고 수동 이전/운영 정책을 설계한 뒤, 사용자 동의를 전제로 날씨·AI 추천을 별도 단계로 추가한다. 이번 MVP 확정 작업에는 새 기능을 추가하지 않는다.

## 포트폴리오 화면 추천

1. **온보딩의 테마·취향 선택:** 앱 목적과 개인화 설정을 보여준다.
2. **옷장 그리드와 2단계 필터:** 검색·분류·반응형 UI의 완성도를 보여준다.
3. **코트/스커트 등록·수정 화면:** 자체 실루엣과 설명, 색상·소재·두께 입력을 보여준다.
4. **서버 개발 옷장의 ready 사진 상세 + 미저장 확인창:** 인증된 사진 표시와 데이터 보호 UX를 별도 캡처로 보여준다.

캡처는 합성/공개 가능한 테스트 자료로 준비하고 이메일·개인 계정·실제 사용자 사진·개발키가 화면에 나오지 않게 한다. 실제 사용자 의류를 포트폴리오 자료로 자동 복사하거나 이번에 새 캡처하지 않았다.

최신 검증 범위와 미검증 항목은 [최종 검증 보고서](validation/portfolio-mvp-1.0-20261112.md)에 구분한다. 과거의 브라우저/HTTP 통합 성공을 이번에 재실행한 결과로 소개하지 않는다.
